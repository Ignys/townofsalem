# Checklist do playtest presencial assistido

Registre aparelho, navegador, versão exibida no painel, código da sala e códigos técnicos de erro. Não use banco de produção para testes destrutivos.

## Entrada e sigilo

- [ ] Mestre cria a sala e copia código/link/QR.
- [ ] Vários celulares entram e recuperam a sessão após refresh.
- [ ] Cada jogador vê somente sua role, objetivo, detalhes, fase e timer.
- [ ] Nenhum jogador encontra votação, formulário de ação, Action Log, roster privado ou resultado secreto.

## Operação do mestre

- [ ] Sorteio e sigilo das roles.
- [ ] Troca livre entre todas as fases.
- [ ] Fase personalizada com minutos/segundos.
- [ ] Timer, pausa, retomada, +30s e encerramento sem avanço automático.
- [ ] Nova Noite cria número e identidade próprios; pausa/retomada não cria outra noite.
- [ ] Checklist respeita ordem, vivos e agrupamentos declarados no catálogo.
- [ ] Ator aparece como nome + role; ação única seleciona seu verbo automaticamente.
- [ ] Targeting respeita quantidade, self-target e alive/dead já modelados.
- [ ] Action Log sobrevive a refresh, aceita edição/cancelamento e evita clique duplo.
- [ ] Notas ficam separadas e não entram no engine.
- [ ] Preview lista inválidos, warnings, mortes, sobreviventes e investigações somente ao host.
- [ ] Explicação causal permite conferir o resultado.
- [ ] Confirmação aplica os efeitos uma vez sem trocar a fase.
- [ ] Rollback restaura apenas os campos tocados e exige novo preview.
- [ ] Noites anteriores e Event History continuam consultáveis.

## Dispositivos e falhas

- [ ] Host em notebook e tablet landscape; fallback mobile utilizável.
- [ ] Jogador em 320 px, 375 px e 430 px.
- [ ] Perda e retorno de conexão em host e jogador.
- [ ] Duas abas do host não aplicam a mesma resolução duas vezes.
- [ ] Jogador removido ou target inválido produz erro legível.
- [ ] Exportação JSON contém Action Log, resoluções e Event History.
